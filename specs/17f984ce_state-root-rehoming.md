# STATE-ROOT RE-HOMING — the kernel accumulates NOTHING from app runs

Run under `adws/adw_sssf_config/sssf.meta11.config.yaml` (protected_files lifted for exactly this
run). NO self-commit, NO push — the chain's commit phases own the landing. Do NOT delete the
meta11 roster in this change (its header says "delete when the feature lands"; landing is the
commit phase's job, and this run still operates under it).

## Goal

Every file generated by mounting/running sandbox or local app workflows moves beside the project
it belongs to. After this change, an app run (local mode, or target mode with `local_path`, or
sandbox-only target mode) leaves ZERO new files in the kernel tree. Kernel-self (vendored) runs
are unchanged.

## State-root rule (the one rule everything derives from)

Resolved per run, from the active roster (`$SSSF_CONFIG`):

- **(a) local mode / target mode WITH `app.local_path` set** → `<local_path>/sssf/`
  Layout: `runs/<id>.json`, `runs/<id>-artifacts/`, `runs/<id>.bundle`, `runs/<id>.watcher.log`,
  `repos/<app>.git` (harvest bare cache), `sssf.db`, `sessions/`, `ui.port`.
  An arming step adds `sssf/` to the app clone's `.gitignore`.
- **(b) target mode WITHOUT `local_path` (sandbox-only users)** → `~/.sssf/apps/<app-key>/`,
  same layout. `app-key` = sanitized `app.repo` basename: basename minus `.git`,
  lowercased, `[^a-z0-9]+` → `-` (e.g. `https://github.com/yhuangsh/hello-server.git` →
  `hello-server`).
- **(c) vendored mode (kernel-self development, no `app.repo`/`app.local_path`)** → the kernel's
  existing locations (`.sandbox/runs/`, `adws/adw_data/`): UNCHANGED.

Legacy readability: reads search the new location first, then legacy `.sandbox/runs/`, so
pre-change records (the ~35 records, 17 bundles, 20 artifact dirs currently in `.sandbox/runs/`)
keep resolving until migrated.

## Step 1 — `run_record.py`: state-root resolution API + `migrate`

File: `sandbox_mount/host/run_record.py` (STDLIB ONLY — it runs on the host before any toolchain
exists; do not add a yaml dependency).

Add:

```python
LEGACY_RUNS_DIR = REPO_ROOT / ".sandbox" / "runs"   # replaces today's RUNS_DIR constant

def app_key(repo_url: str) -> str: ...              # basename minus .git, sanitized per rule (b)

def resolve_state_root(roster_path: Path | None) -> Path | None:
    """None = vendored/kernel mode. (a) local_path set -> <local_path>/sssf;
    (b) app.repo set -> ~/.sssf/apps/<app-key>. Parse the roster's `app:` block with a
    line-based scan (two-space indent, ignore `#` comments and blank lines) for `repo:` and
    `local_path:` — the same convention the just recipes use with awk. `~` expands.
    A commented-out `local_path:` does NOT count."""

def state_root() -> Path | None:
    """resolve_state_root(os.environ.get("SSSF_CONFIG")); None when unset/unparseable —
    callers then fall back to legacy, so `run_record.py list` in doctor keeps working
    without SSSF_CONFIG."""

def runs_dir() -> Path:
    """state_root()/runs, or LEGACY_RUNS_DIR when vendored or unresolved."""

def resolve_record_path(run_id) -> Path:
    """Read resolution: runs_dir()/<id>.json if it exists, else legacy, else the new path
    (so the FileNotFoundError message names the canonical location)."""
```

Semantics changes:

- `create()` writes to `runs_dir()` (mkdir parents). `path()` (used by `path` CLI) → `runs_dir()`.
- `get`/`set`/`close`/`_write` resolve via `resolve_record_path` — a record that exists ONLY in
  legacy is read and updated IN PLACE (old runs keep working pre-migration).
- `list_runs()` merges `runs_dir()/*.json` + `LEGACY_RUNS_DIR/*.json`, dedupe by run_id
  (new location wins), same sort. `runs_table.py` needs no change (stdin).
- New CLI subcommands for shell consumers (recipes must stop hardcoding `.sandbox/runs`):
  - `run_record.py state-root` → prints the resolved root, empty line for vendored/unresolved
  - `run_record.py runs-dir` → prints the effective runs dir
- New CLI subcommand `migrate` (requires SSSF_CONFIG; refuses vendored mode):
  for each legacy `.sandbox/runs/<id>*` item (`<id>.json`, `<id>-artifacts/`, `<id>.bundle`,
  `<id>.watcher.log`), move it into `runs_dir()`. Move semantics: `shutil.move`; for the record
  file itself, write-then-verify-then-remove (read back the destination JSON and compare before
  deleting the source) so a failed move never loses a record — NON-DESTRUCTIVE on failure:
  leave the source, print the error, continue, exit 1 if anything failed. Print one report line
  per item moved. Skip items already present at the destination (idempotent).
- The harvest fields (`base_ref`/`base_sha`/`merge_mode`/`merge_sha`/`harvest_state`) already
  live in FIELDS — they move with the record files automatically; just keep them.
- Update the module docstring: records live "under the per-app state root (`<local_path>/sssf/runs`
  or `~/.sssf/apps/<app-key>/runs`), legacy `.sandbox/runs/` still readable".

## Step 5 — payload-aware commit routing (local mode)

Today: planner/documenter write `specs/<adw_id>_*.md` / `app_docs/<adw_id>_*.md` into the KERNEL
tree (agent cwd = `run.repo_root`); commit phases `git add -A` in the payload clone, so in local
mode those products are committed NOWHERE and pollute the kernel tree.

Change (LOCAL mode only — `cfg.app.local_path` set; target/sandbox keeps the teardown-tar
behavior; vendored = payload IS the kernel, no-op):

- New helper in `adws/adw_modules/git_helper.py`:

```python
def route_kernel_products(adw_id: str, payload: Path, kernel_root: Path) -> list[Path]:
    """Local mode: MOVE this run's kernel-side products — specs/<adw_id>_*.md,
    app_docs/<adw_id>_*.md (glob both, only this run's id) — into the same relative
    paths under `payload` (mkdir parents). Returns moved files. No-op when
    payload == kernel_root (vendored) or no matches."""
```

- Call it immediately before EVERY commit phase in the committing chains:
  `adws/adw_plan_build.py:43-46`, `adws/adw_plan_build_test.py:73-76`,
